1What we're building

An automated pipeline that produces a comprehensive, evidence-backed code quality report for this codebase — in the spirit of a SonarQube scan, but going further: it pairs deterministic static analysis with an AI review layer that reads the code directly, catching logic bugs, race conditions, and framework-version-specific issues that pattern-matching tools structurally cannot express. Every finding is anchored to a specific file and line, so the report is auditable, not a generic checklist.

Deterministic analysis

ESLint, npm audit, and first-party pattern rules — exhaustive and fully reproducible.

AI deep-read

Independent review of the actual code, catching what pattern matching structurally can't.

It runs as a one-time baseline audit of the full codebase — the right shape for an initial quality assessment, a handoff, or a periodic health check.

Enumeration & mapping

Every file in src/ is walked, classified, and accounted for, giving an honest coverage figure rather than a sampled guess.

Dependency graph

The codebase map is built with the TypeScript compiler itself — the same resolution the project's own build uses — so path aliases, barrel re-exports, and dynamic imports resolve exactly:

That graph is then split into bounded modules of related files, each small enough for a focused, thorough AI read.

Version-rules brief

Before any code is read, the pipeline resolves a version-specific rules brief via Context7 for the exact framework versions this repo runs — next@15.5.18, react@19.2, next-auth@5.0.0-beta.26 — covering current APIs and known upcoming breaking changes. Findings are checked against the real, current contract for this stack, not generic assumptions. For example, it lets the review proactively note that Next.js 16 renames middleware.ts to proxy.ts, and that src/middleware.ts will need that rename on the next major upgrade — a fact invisible to a linter.

Static analysis, judgment, AI deep-read & synthesis

ESLint, npm audit, and first-party pattern rules run across the whole codebase. Every static finding passes a skeptical confirm/reject review before it's allowed into the report. Each bounded module is separately read by an AI reviewer with no pre-filtering, looking for the class of issue static tools can't express — leaks, race conditions, unsafe data handling, version-specific API misuse. A final synthesis pass reasons across all findings together, surfacing systemic patterns no single file reveals on its own.
